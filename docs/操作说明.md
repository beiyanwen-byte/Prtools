# GitHub PR Desk 桌面版操作说明

## 一、运行环境

### Windows

- Python 3.10 或更高版本，安装时选择包含 Tcl/Tk。
- Git for Windows 或已配置的 Git 命令行。
- 如需使用 WSL 仓库，安装对应 WSL 发行版及发行版内的 Python 3、Tk 和 Git。

启动：双击项目根目录的 `打开PR工具.cmd`。

### Linux

- Python 3。
- Python Tk 支持；Debian/Ubuntu 常见安装：`sudo apt install python3-tk`。
- Git；SSH 客户端可用于 SSH origin。

启动：运行根目录的 `启动桌面.sh`，或执行：

```sh
python3 app/desktop_gui.py
```

### macOS

- Python 3 with Tk；官方 python.org 安装包通常包含 Tk。
- Git；GitHub SSH 客户端可作为可选配置。

启动：运行根目录的 `启动桌面.command`，或执行：

```sh
python3 app/desktop_gui.py
```

启动后会检测 Python、Tk、Git、SSH 和平台。缺少依赖时只显示修复提示，不会自动安装、修改系统或读取凭据。

## 二、选择仓库

程序打开后先选择工作文件夹。左侧只列出该目录和直接子目录中的 Git 仓库。点击仓库后自动读取 origin、验证账号和加载远程分支；工作文件夹和分支选择会按仓库保存到本机忽略的偏好文件，不会写入项目仓库。

## 三、Git 与 GitHub Token

程序优先使用目标仓库所在系统已经配置的 Git credential helper。优先使用 HTTPS 和当前环境的凭据，不读取 SSH 私钥文件。

### PAT 不等于账号密码

GitHub HTTPS 操作需要：

- 用户名：GitHub 登录名。
- 密码位置：Fine-grained personal access token 或 classic PAT。

不要把 PAT 粘贴到聊天、项目文件、启动脚令、`git config` 或命令参数中。一个账号对应一个仓库凭据；不同仓库可以保存不同账号的 PAT，不会全局覆盖其他仓库。

Windows 可尝试保存到 Windows Credential Manager。若安全保存失败，程序只在本次进程内使用该 PAT，并明确提示。Linux/macOS 不自动覆盖现有凭据管理器；如果没有可用安全存储，程序可只在内存使用该令牌。

### Fine-grained PAT 建议权限

选择目标组织或个人账号，建议只选择需要的仓库。按功能授予最低权限：

| 功能 | Repository permissions |
|---|---|
| 读取仓库、分支、提交和差异 | Contents: Read-only；Metadata: Read-only 通常自动包含 |
| 检查 PR | Pull requests: Read-only |
| 创建 PR 或请求审核人 | Pull requests: Read and write |
| 创建远端 Tag | Contents: Read and write |
| 查看 Workflow 和 Job | Actions: Read-only |
| 查看部署环境和状态 | Actions: Read-only；Deployments: Read-only |
| 审批待部署环境（只在明确授权时） | Actions: Read and write 或 Deployments: Read and write，需账号也具有环境审批权限 |

只查看 Workflow 不需要 `Actions: Write`；审批部署是另一项操作，需用户明确确认。不要给仓库删除、组织管理、Secrets 或不相关工作流权限。

## 四、主要操作

1. 选择工作文件夹和仓库。
2. 选择不同的远程 Base 和 Source；程序会记住该仓库的上次选择并尝试比较。
3. 在代码差异页查看目录树，目录行汇总文件数和增删行数；点击文件查看 Patch。
4. 在 Source 提交页按作者时间查看提交；点击提交加载完整提交说明。
5. 在 PR 页编辑标题和正文、搜索审核人、检查已有开放 PR；创建和审核人请求均需明确确认。
6. 在 Tags 页按仓库分支筛选、Tag 名搜索和关联分支查看标签；默认只显示最新五个匹配 Tag。
7. 在 Workflow / 部署页查看 build-and-push 或 build-and-deploy 的最近运行；默认状态不会自动轮询，点击刷新更新快照。
8. 在运行日志查看脱敏 Fetch 和操作记录。

## 五、仓库默认 Workflow

- 仓库名为 `tsp-common-model` 或 `tsp-common-lib`：默认 `build-and-push.yaml`。
- 其他 `tsp-*` 仓库：默认 `build-and-deploy.yaml`。
- 如果页面允许手工输入 Workflow 名，输入的名称只用于同一次读取；不能包含 `/`、`\\` 或 `..`，名称保留在内存，不写入本地偏好。

Workflow 运行结果只描述该次历史运行，不保证环境当前仍运行该版本。关联分支只表示提交可达关系，不证明 Tag 的创建来源。

## 六、隐私与本地数据

下列数据不会被提交到发布仓库：

- `.preferences.json` 和本地 Tag 命名规则。
- Windows Credential Manager 中按仓库保存的 Token。
- 本机工作目录、账号、邮箱或绝对路径。
- Git 私钥、`.env`、日志、虚拟环境、IDE 配置和缓存。

发布目录只包含桌面应用、合成测试和操作文档，不包含网页服务、启动码、浏览器服务、旧历史或本地凭据。

## 七、测试

从项目根目录运行：

```text
python -B -m unittest discover -s tests -t .
```

测试使用合成数据、模拟 GitHub 响应和离线 Windows/WSL 启动桩，不创建真实 PR、Tag、审核人请求或部署批准。需要真实环境和账号时，另行执行明确标记为 live 的测试，并确认仓库和权限。
