# GitHub PR Desk 桌面使用说明

## 一、运行环境

- Windows：安装 Python 3.10 或更新版本，并选择包含 Tcl/Tk 的安装方式；同时安装 Git。
- 若要访问 WSL 内的仓库，还需要相应的 WSL 发行版、Python 3 和 Git。Windows 桌面窗口会调用对应发行版中的后台进程。
- 必须能访问 GitHub，且所选账号对目标仓库具有相应权限。

双击项目根目录的 `打开PR工具.cmd` 启动。首次使用时选择工作文件夹；左侧只扫描该文件夹本身和直接子目录中的 Git 仓库。点击仓库后自动连接。也可以从项目目录手动运行：

```text
py -3 app/desktop_gui.py
```

## 二、Token 与 GitHub 权限

程序优先使用目标仓库所在环境配置的 Git credential helper。连接失败时，可在桌面窗口中选择“使用 Token”并输入个人访问令牌；验证成功后，Windows 版本会尝试按仓库保存到 Windows 凭据管理器。若安全保存失败，界面会明确提示仅在本次会话使用。

建议使用 **Fine-grained personal access token**，选择目标组织或账号作为 Resource owner，并在 Repository access 中仅选择需要使用的仓库。按功能授予最低权限：

| 功能 | Repository permissions |
|---|---|
| 读取仓库、远程分支和代码差异 | `Contents: Read-only`；`Metadata: Read-only` 通常自动包含 |
| 检查 PR | `Pull requests: Read-only` |
| 创建 PR、请求审核人 | `Pull requests: Read and write` |
| 创建远端 Tag | `Contents: Read and write` |
| 查看 Workflow 运行及 Job 状态 | `Actions: Read-only` |

只查看 Workflow 不需要 `Actions: Read and write`，也不需要修改 Workflow 文件的权限。组织可能要求管理员审批、SSO 授权或其他策略；Token 不会赋予账号本身没有的仓库权限。如果必须使用 classic Token，私有仓库通常需要范围较宽的 `repo` 权限，应先确认组织策略。

不要把 Token 粘贴到聊天、命令参数、项目文件或示例配置中。Git helper 的存储安全性取决于用户配置；例如 `store` helper 可能以明文保存凭据，建议使用系统安全凭据管理器。

## 三、日常操作

1. 选择工作文件夹并点击左侧的仓库。连接成功后，界面显示账号与远程分支。
2. 搜索并选择不同的 Base 和 Source。程序自动记住该仓库的分支选择，并自动比较。
3. 在“代码差异”查看目录树；点击文件显示差异，目录行汇总变更数量。Source 提交页提供作者时间、作者、标题和按需读取的提交说明。
4. 在“PR 与审核人”检查已有 PR、编辑标题和正文，并按需选择审核人。保存的审核人下次需要重新验证。创建 PR 和请求审核人需要明确确认；结果不确定时先到 GitHub 检查，不要自动重试。
5. 在“Tags”查看远端 Tag。分支筛选和 Tag 搜索分开；分支头匹配及关联分支**不证明** Tag 从哪个分支创建。创建远端 Tag 前须核对仓库、分支、提交和名称并确认；已有同名 Tag 不会被覆盖。
6. 在“Workflow / 部署”查看 `build-and-deploy.yaml` 的 Tag 运行结果，支持手动刷新和继续加载。页面只读，不会触发、重跑、取消或审批部署。Job 成功是该次运行的历史结果，不保证环境当前仍在运行该版本。
7. 在“运行日志”查看本次后台会话的脱敏操作记录，包括 Fetch 新增和更新的远程分支。

## 四、本地偏好与可选命名规则

工作文件夹、每个仓库的分支选择和 PR 草稿保存在被 Git 忽略的本地 `.preferences.json`；该文件不应提交，也不应包含 Token。用户输入的 Token 不写入此文件。

可以在本地偏好中增加可选的 Tag 规则。以下仅为**合成示例**，应按自己的需要填写；编辑已有文件时请保留其他字段，不要覆盖已有偏好：

```json
{
  "desktop_tag_rules": {
    "branch_filter": "release-*",
    "suggestions": [
      {"branch": "release-example", "prefix": "v2.5.", "suffix": "-demo"}
    ]
  }
}
```

对于配置了规则的分支，创建 Tag 弹窗会只读查询整个远端仓库，建议最大数字加 1。没有匹配版本或查询失败时可手动输入；不会覆盖用户输入，真正创建前仍检查远端是否重名。

## 五、测试与隐私

从项目目录运行离线测试：

```text
python -B -m unittest discover -s tests -t .
```

测试使用合成数据和模拟接口，不创建真实 PR、Tag 或部署。部分界面测试需要可用的 Tk 图形环境；不具备相应环境时会跳过。

本地偏好、凭据、日志、虚拟环境和 IDE 数据不应提交。`.gitignore` 提供常见保护，但不能代替提交前检查；确认 Git 跟踪文件和提交内容不包含 Token、个人信息或本机绝对路径。隐私扫描是启发式检查，不保证覆盖所有情况。
